# Work005-002 Nano Banana Rule 검증 실험계획서

## 1. 실험 공통 통제

- **입력 근거**: Work005-001 결과만 사용한다.
- **실행 금지**: API 호출, Nano Banana 호출, 이미지 생성, Engine/Builder/Registry/Module 수정, Prompt 승인.
- **비교 원칙**: 한 실험에서는 `변경되는 Rule`만 다르게 하고 원본·요청·모델·출력 설정·반복 수를 고정한다.
- **모델 원칙**: NB2를 1차로 사용하고 결과가 기준 미달·모호하거나 복합성이 높을 때만 동일 조건을 Pro로 확대한다. 모델 우열은 사전 가정하지 않는다.
- **평가 원칙**: `Hard Gate → 100점 Rubric → Blind A/B → 반복 안정성` 순으로 판정한다.
- **기준선**: Work005-001 Carat 기본형의 기능적 골격을 baseline으로 사용하되 공개 Prompt 원문은 Runtime에 복사하지 않는다.

## EXP-001 — 동일인 보존 표현 비교

- **우선순위 / Module**: P0 / `core.identity`, `core.facial-geometry`
- **실험 목적**: Preserve / Keep / Maintain과 속성 구체성의 동일인 보존 효과를 분리한다.
- **검증하려는 Rule**: R002 Recognizable Same Person, R003 Facial Geometry Invariants
- **변경되는 Rule**: A=`Preserve same person`, B=`Keep same person`, C=`Maintain same person`, D=canonical 동사+얼굴 구조 속성 목록. 문구는 의미 외 길이를 최대한 맞춘다.
- **고정되는 Rule**: Source of Truth, 피부·헤어·표정 잠금, 의상/배경 변경 요청, 조명, 구도, output config.
- **예상 결과**: 동사 3종 차이보다 D의 구체적 불변속성이 identity/geometry 변동을 줄인다.
- **실패 시 예상 원인**: 의미상 동일 문구, 표본 부족, 스타일 변경 강도가 너무 약함, 평가자의 identity 판정 불일치.
- **성공 기준**: Hard Gate 100%, D가 baseline 대비 identity/geometry 평균 향상 및 Blind win rate 60% 이상, 어느 원본에서도 치명 회귀 없음.
- **Benchmark 평가 항목**: identity 20, facial geometry 12, identity variance, eye/nose/jaw drift, A/B preference.

## EXP-002 — 피부 보존 규칙 검증

- **우선순위 / Module**: P0 / `core.skin-tone`, `core.retouch-intensity`
- **실험 목적**: 피부 질감·피부색·모공·특징적 잡티 보존에 가장 효과적인 구조를 찾는다.
- **검증하려는 Rule**: R007 Natural Skin Tone, R008 Restrained Retouch
- **변경되는 Rule**: A=`natural skin`, B=tone만 원본 고정, C=tone+texture, D=tone+texture+restrained retouch. 잡티는 제거 대상이 아니라 정체성 특징 보존 항목으로 둔다.
- **고정되는 Rule**: identity, facial geometry, hair, expression, wardrobe/background delta, crop, lighting.
- **예상 결과**: D가 플라스틱 피부와 미백/색조 drift를 가장 줄인다.
- **실패 시 예상 원인**: 조명 변화가 tone 평가를 교란, 원본 해상도 부족, `restrained` 해석 불안정.
- **성공 기준**: 피부 Hard Gate 위반 0, D가 skin score 4/5 이상, naturalness 비열등, 원본 피부톤·질감의 관찰 가능한 특징 유지.
- **Benchmark 평가 항목**: tone fidelity, pore/texture retention, blemish retention, overbeautification, naturalness, lighting-normalized review.

## EXP-004 — 표정 보존 규칙 검증

- **검증하려는 Rule**: R004 Characteristic Impression Preservation, R011 Expression Envelope
- **변경되는 Rule**: A=`keep expression`, B=baseline impression 보존, C=baseline+허용 delta(예: 미세한 자연 미소), D=`do not change expression`.

- **실패 시 예상 원인**: 인상 평가 주관성, 원본 표정 다양성 부족, 미소 요청과 잠금 충돌.

## EXP-005 — 원본 기준(Source of Truth) 규칙 검증

- **우선순위 / Module**: P0 / `core.source-of-truth`
- **실험 목적**: 업로드 이미지를 유일한 인물 기준으로 선언하는 효과와 위치를 검증한다.
- **검증하려는 Rule**: R001 Uploaded Portrait Source of Truth
- **변경되는 Rule**: A=없음, B=첫 문장, C=identity 직전, D=후미 배치.
- **고정되는 Rule**: identity/geometry 상세, edit boundary, 스타일 변경량, 전체 문구와 출력 설정.
- **예상 결과**: B 또는 C가 얼굴 보존과 reference adherence를 높인다.
- **실패 시 예상 원인**: 단일 참조에서는 역할이 이미 명확, 위치 영향이 없음, identity Rule 효과가 지배.
- **성공 기준**: 승자 조건이 identity/change control에서 baseline 대비 우세하고 치명 회귀 없음. 차이가 없으면 더 짧은 A를 비열등 승자로 판단 가능.
- **Benchmark 평가 항목**: reference adherence, identity, locked attribute violations, order sensitivity.

## EXP-006 — 편집 허용 범위(Edit Boundary) 규칙 검증

- **우선순위 / Module**: P0 / `core.edit-boundary`
- **실험 목적**: 변경 가능 요소와 유지 요소를 명시할 때 collateral edit가 감소하는지 검증한다.
- **검증하려는 Rule**: R019 Unspecified Attributes Locked, R012의 authorization 부분
- **변경되는 Rule**: A=변경 대상만 기술, B=변경 대상+보존 목록, C=allowedChanges/lockedAttributes 구조, D=`요청 외 변경 금지` 단문.
- **고정되는 Rule**: 동일 배경·의상 변경 요청, identity contract, 조명·구도·출력.
- **예상 결과**: C가 요청 이행을 유지하며 잠긴 속성 위반을 가장 줄인다.
- **실패 시 예상 원인**: 잠금 항목 과다로 요청도 억제, 상충 지시, 모델이 schema-like 표현을 약하게 해석.
- **성공 기준**: allowed change 성공률 90% 이상, locked violation 0, identity/geometry Hard Gate 100%.
- **Benchmark 평가 항목**: change precision, collateral edit count, request adherence, boundary conflict.

## EXP-007 — 프롬프트 길이 비교

- **우선순위 / Module**: P1 / Prompt Compiler 전반
- **실험 목적**: 같은 의미를 가진 짧은·중간·긴 Prompt의 품질과 안정성을 비교한다.
- **검증하려는 Rule**: R001~R019의 Portrait 공통 묶음
- **변경되는 Rule**: Short=핵심 계약, Medium=속성별 최소 충분 구조, Long=중복 보존·negative를 포함한 Carat형 장문. 의미 범위와 스타일 목표는 동일하게 맞춘다.
- **고정되는 Rule**: module order, 원본/요청, 모델/출력, 평가 기준.
- **예상 결과**: Medium이 Short보다 누락이 적고 Long보다 충돌·분산이 낮다.
- **실패 시 예상 원인**: 조건 간 의미량 불일치, 길이가 아니라 구체성이 원인, 긴 조건에만 추가 정보 포함.
- **성공 기준**: 품질 최고 또는 2점 이내 비열등 조건 중 가장 짧은 variant, Hard Gate 회귀 없음.
- **Benchmark 평가 항목**: 전체 100점, instruction omission, conflict rate, character/token proxy, variance.

- **실험 목적**: 헤어 정돈을 허용하면서 헤어 정체성을 보존하는 최소 delta를 찾는다.
- **검증하려는 Rule**: R006 Grooming Delta Only, R005
- **변경되는 Rule**: A=`neat hair`, B=hair preservation만, C=preserve+flyaway cleanup only, D=C+명시적 locked hair attributes.
- **고정되는 Rule**: 같은 잔머리 fixture, identity/skin/expression, 배경·조명·구도.
- **예상 결과**: C/D가 잔머리는 줄이되 가르마·볼륨·길이를 유지한다.
- **실패 시 예상 원인**: 정돈 성공 정의 불명확, hair segmentation 오류, 너무 강한 잠금으로 변화 없음.
- **성공 기준**: grooming 목표 4/5 이상, hair fidelity 4/5 이상, hairstyle replacement 0.
- **Benchmark 평가 항목**: flyaway cleanup, hairline/parting/volume/length, boundary artifacts.

## EXP-016 — 머리 방향과 시선 분리 검증

- **우선순위 / Module**: P1 / `id.pose.head-orientation`, `id.gaze.target`
- **실험 목적**: front-facing과 lens gaze를 분리할 때 정면 성공률이 향상되는지 검증한다.
- **검증하려는 Rule**: R009 Front Head Orientation, R010 Lens Gaze
- **변경되는 Rule**: A=`front-facing`, B=head orientation만, C=lens gaze만, D=둘을 독립 문장으로 결합.
- **고정되는 Rule**: identity contract, expression, crop, style, 출력.
- **예상 결과**: D가 머리·눈 축을 모두 만족하지만 포즈 보정량이 큰 원본에서는 identity 회귀 위험이 있다.
- **실패 시 예상 원인**: 원본 측면각이 큼, 눈 비대칭 재생성, 정면화가 허용 범위를 넘음.
- **성공 기준**: pose와 gaze 각각 4/5 이상, identity/geometry 비열등, 눈 artifact 0.
- **Benchmark 평가 항목**: yaw/pitch 관찰 등급, binocular gaze, eye geometry, identity.

## EXP-017 — Aspect Ratio 전달 계층 검증

- **우선순위 / Module**: P2 / `output.image-config.aspect-ratio`
- **실험 목적**: Prompt 문구와 API output config 중 비율 전달의 안정적 위치를 결정한다.
- **검증하려는 Rule**: R017 Aspect Ratio via Output Config
- **변경되는 Rule**: A=text only, B=config only, C=text+config, D=text와 config 충돌(guard fixture).
- **고정되는 Rule**: 원본·Prompt 의미·crop·모델·해상도·반복.
- **예상 결과**: B/C가 exact ratio에 안정적이며 D는 config 우선 또는 사전 validation으로 차단되어야 한다.
- **실패 시 예상 원인**: 실행 환경에서 설정 미지원, 자동 crop 후처리, 모델별 API 차이.
- **성공 기준**: exact ratio 100%, B가 crop 품질 비열등이면 Prompt 중복 제거, 충돌 fixture는 사전 오류 처리.
- **Benchmark 평가 항목**: exact dimensions/ratio, crop regression, conflict handling, prompt redundancy.
